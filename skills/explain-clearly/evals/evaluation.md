## 验证过程

1. 写技能前，独立代理未读取解释技能，回答榫卯、Transformer、区块链和平均值四题。保留原始输出与审查；其中榫卯已有清楚内容，不把它人为判错。观察到的失败主要是未解释术语、额外分类、背景段和专家指标。
2. 初版对六个用例试用，并由另一独立代理审查。发现防拔出机制只列名字、区块链接受规则解释不足、Transformer 仍默认追加背景。
3. 增强“选一个机制讲清”“不以新专业名词结束因果链”和交付前收束后，再试六个用例。榫卯木销如何阻挡、区块链累计工作量和示例数字身份变清楚。
4. 收紧“只解释起作用过程时，不顺带展开制造/训练或通用可靠性评价”。针对 Transformer 和未在示例中出现的空调再试用。第一次范围试验的提示误写成“两段用户答案”，使两题各被压成一个长段落；该次不用于判断默认版式。纠正测试提示后，最终输出恢复自然分段和真实步骤列表。

## 观察结果

| 用例 | 观察 |
| --- | --- |
| 榫卯 | 定义榫头和卯眼；侧壁如何限制位移；木销横穿两木件如何挡住退出；不承诺全方向锁死。 |
| Transformer | 定义 token/数字表示；注意力权重如何组合信息；当前位置及前文的范围；最后位置预测、选择和重复。最后一轮没有再附训练背景课或泛化免责声明。 |
| 区块链 | 哈希变化可被发现，但可以重算；接受改写仍取决于共识规则；工作量证明例子说明累计工作量，不将不可篡改绝对化。 |
| 平均值 | 假设数字的平均计算正确；区分总体与个体；保留本次测试范围，没有扩展延迟分位数。 |
| 递归 | 两句话，包含同类更小问题、终止条件以及向终止条件推进。 |
| 梯度下降 | 匹配线性代数背景，说明参数、损失、梯度和更新；保留步长条件与不保证全局最优。 |
| 空调（新题） | 先解释热量从哪里到哪里，再说明吸热、压缩升温、放热和降压；分清室内热量与耗电产生的热量。 |

这些是对模型输出的人工行为审查，不是读者实验、模型基准或效果百分比；不能证明所有未来回答都同样清楚。Transformer/空调最终输出仍有进一步压缩空间，但不再靠删除机制来压缩。
