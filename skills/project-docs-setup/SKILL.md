# 项目文档初始化

把现有项目事实整理成后来的人和 Agent 找得到的文档入口。通常每个项目运行一次；项目结构变化时可再次运行。不要为尚未确定的内容创建空白 `CONTEXT.md`、ADR 或设计稿。

## 先看现场

读取项目根目录、README、现有文档索引、代码与配置入口，以及当前平台实际生效的 `AGENTS.md`、`CLAUDE.md` 或等价规则。若已有设计稿、`CONTEXT.md` / `CONTEXT-MAP.md`、ADR，也一并查看。确认哪些文件已经承担项目概览、设计、领域语言、架构和运行说明的职责，避免再建平行答案。

## 建立入口

1. 用现有代码、配置和已确定的设计核实项目目的、现有能力、启动或使用方式。缺少关键事实时只问阻止准确落笔的问题；尚未实现的能力明确标为计划。
2. 在已有 README 或项目概览文档中补足必要的定位与导航；若两者都没有，创建简短 README。只写有证据的当前事实和相关文档链接。
3. 沿用现有文档路径；没有约定时，设计稿放 `docs/specs/`，领域词汇放根目录 `CONTEXT.md`，重要决策放 `docs/adr/`，单次功能计划放 `.planning/<feature>/`。目录与文件按需创建，不生成占位内容。
4. 若项目有 Agent 规则文件，在实际被加载的文件中加一段简短导航：做功能前读相关设计稿、领域词汇和 ADR；实施状态读对应 `.planning/<feature>/`；完成后核对长期文档。若没有规则文件，只在这段导航确实会帮助后续 Agent 时创建当前平台原生文件；不要同时创建两份独立规则。
5. 检查新增链接和路径真实可用，说明哪些文档已建立、哪些尚无内容。

## 与其他 skill 的边界

- 本 skill 建文档入口，不替用户设计新功能。需求或行为仍有实质歧义时用 `brainstorming`。
- 术语与领域边界由 `domain-modeling` 澄清并写入 `CONTEXT.md`；本 skill 不猜测词义。
- 单次功能的步骤和状态由 `planning-with-files-zh` 管理；本 skill 不在 README 中复制任务计划。
- 后续代码变化与文档不一致时由 `neat-freak` 对齐；再次运行本 skill 主要处理入口和布局变化。
