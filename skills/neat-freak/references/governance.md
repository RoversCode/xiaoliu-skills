# 规范执行审计细则

规则来自当前用户、项目和实际加载链。本 reference 只提供相关规则的核对方法，不扩展请求范围。只读审查只分析报告，即使修复安全且可逆也不写入。

## 找出本次适用的约定

从已加载规则和本次变更开始，只补读相关但尚不明确的来源，记录需要引用的原文出处；不要从头扫描所有祈使句。

| 本次涉及的约定 | 可用证据 |
|---|---|
| 命名或目录纪律 | 受影响位置的清单及例外条款 |
| 必备文件 | 相关文件存在性和必要内容 |
| 同源或加载顺序 | `readlink`、realpath、导入和平台诊断 |
| 敏感信息与 ignore | 相关 tracked files、ignore 规则；风险需要时用现有 scanner |
| 命令、URL、服务声明 | 对应配置、服务或真实运行路径 |
| 发布与清理次序 | 项目明文要求的记录、状态和授权证据 |

行为偏好同样需要遵守，但不为其新增机械审计或门禁。

## 规则链与范围

复用环境已给出的 Agent、cwd、规则及加载关系。只有加载关系影响本次结论且仍不明确时，才定向核对当前平台的 override、fallback、路径规则或相关上级来源。发现其他平台目录不代表需要审它。

- 当前项目任务只审受影响内容；不默认枚举同级项目、祖先目录或用户 home。
- 跨项目影响先给出已知依赖证据，只查实际相关 consumer；查到依赖不等于获准修改。
- workspace 或全局配置审查须属于用户请求范围；只读权限不等于需要顺手扩大盘点。
- 规则同源方向以项目声明和加载机制为准，不能确定时报告相关冲突，不强行统一。

## 根据模式处置

**已授权同步**：在范围内可直接修正文档事实、死链接或相关规则，但先确认事实来源，保留有效注释和仍有用途的历史。不需要用户为同一个已授权、无状态变化的动作重复确认。

**需要额外决定**：对象超出范围、权威来源无法裁决、状态变化导致原授权不再适用，或现场有明确的最终确认要求时，准备具体证据和动作清单后再询问。删除、迁移、外部消息等依既有授权及风险规则执行；“收尾”不自动授予这些权限。

**只读报告**：只读任务、范围外发现、平台禁止直接修改的生成内容，或事实尚不能核验时，仅报告。未解决的相关项标为 `pending`；无关项不变成新的待办。

## 规则质量

只在本次接触的相关规则中识别死引用、矛盾、重复、过载或无法执行的要求。跨设备路径不能因本机不存在就删除；重复内容应明确权威位置和真实读者，不机械删历史。

反复出现的违规可说明现有约束不够有效，但不按次数自动新增 check/hook/test。先判断根因与收益；有必要且在用户授权范围内才实现，否则给出具体建议。已有项目检查继续遵守。

## 报告

对需要用户决定的相关问题给出证据/出处、范围、影响、推荐动作及未执行原因。无需为无关面填固定矩阵，也不用“发现 N 个问题”代替判断材料。报告必须区分建议、已执行动作和仍待确认的事实。
