# 项目知识收尾

使下次接手的人从现役文档找到与实现一致的答案。这个 skill 负责更新长期文档和报告未闭合事项；`.planning/<feature>/` 的三份文件只作执行证据。按任务范围选择轻量或完整审计，不因小改动强制检查部署、记忆等无关面。

## 选择范围与证据

先读本次设计稿、计划、代码差异、现有 README / 架构 / 使用文档、相关 `CONTEXT.md` 与 ADR，以及实际生效的 Agent 规则。只对受影响的知识面修改；项目既有文档布局优先。可用 [变更影响矩阵](references/sync-matrix.md) 找需要核对的读者和文件。

仓库较大、需要机械盘点 Markdown 和规则文件时，可在 Bash 可用的环境运行 `bash <本 skill 所在目录>/scripts/audit-inventory.sh <project-root>`；其他环境用文件搜索和 Git 命令做等价只读盘点。脚本只列路径与元数据，不能代替阅读受影响内容。

对每条重要差异明确：当前事实来源 → 过期说法 → 修改位置 → 验证方法。代码与配置能证明实现内容；声称“已部署”或“用户已经看到”还需相应运行证据。无法验证的状态标明待验证，不写成现役事实。发布、多环境或跨项目收尾时再读 [证据与终态](references/verification.md)。

## 更新

1. 就地修正 README、架构、使用或运维文档中的过期事实，删去重复的现役解释。设计与实现偏离时，修订设计稿或清楚标出被取代的决定；不要让两个版本同时自称现役。
2. 领域词义或上下文边界变化时调用 `domain-modeling`；只有符合其条件的决策才新增或更新 ADR。不要把这些长期结论只留在 `findings.md`。
3. 只在实际加载的 Agent 规则文件里保留必须遵守的项目边界、命令和文档入口。详细机制属于 docs；规则链与平台路径不明时读 [平台规则](references/agent-paths.md) 和 [规范审计](references/governance.md)。不强制创建第二份 `AGENTS.md` 或 `CLAUDE.md`。
4. 对照 `.planning/<feature>/` 的验收与验证记录核实状态，补记收尾结果。完成的计划文件可保留供复核；需要清理时先确认其信息已进入权威文档并遵守当前用户授权和项目规则。其他旧副本、调试文件、未集成分支也按实际风险处理，不能仅凭文件名判定可删除。

项目或用户明确授权维护 Agent 记忆时，先辨认它是人工可编辑还是平台生成；未获准或机制不明时只读。外部发布、删除、迁移和代发遵守当前环境及用户授权，不由本 skill 自行扩权。

## 验证与交接

运行与改动相称的检查：文档链接、相关测试、构建或真实运行路径；没有执行的检查如实说明。最终报告说明改了哪些权威文件、证据支持的当前状态，以及仍待确认或超出本次范围的事项。若只是文档同步，不宣称代码、部署或整个工作区已经完成收尾。
